Idea TitleProposed Solution · 2 / 6

One passive pipeline. Six threat classes. Zero packets sent back.

StealthTap sits behind a mirror port or hardware diode. It only watches — no probes, no completed handshakes, no blocking. Every verdict comes from passively observed metadata: flow records, DNS queries, TLS fingerprints, OT function codes. Payload is never decrypted.

How it addresses the problem

  • Four interchangeable ingest paths — upload PCAP, live NIC capture, live streaming (Zeek→Redpanda), offline batch — feed one detection stack and one alert schema.
  • Read-only by construction — the capture NIC gets no IP, ARP off, no route; the sensor container drops every capability except NET_RAW, publishes no ports, runs read-only.
  • Near real time — kernel-level capture + phase-split scoring; measured detection latency 157 ms p50 on the live path.
  • Explainable output — every alert carries a MITRE ATT&CK mapping, the evidence, which tool fired, and a chain-of-custody hash.

Deliberate tools, wired into one coherent pipeline

Protocol parsing

  • Zeek 6.0.3 + 6 ICSNPP OT plugins — Modbus, DNP3, S7comm, EtherNet/IP, OPC-UA, PROFINET
  • In-process flow assembler with real JA4 + Modbus/DNP3 decode for the live path

Signatures & rules

  • Suricata 7 + 20,829 ET Open rules (concurrent with Zeek)
  • YARA ~401 rules on cleartext-extracted files · MITRE BZAR for SMB lateral movement
  • ENG01–13 behavioural engines — rate/entropy, CV-periodicity, fan-out, byte-ratio, OT command codes

ML & serving

  • XGBoost + Isolation Forest per family → ONNX Runtime (CPU, no GPU)
  • One feature_extraction module for train and serve — no train/serve skew
  • FastAPI + SSE · PostgreSQL · Redpanda+Faust · React/TS dashboard · Docker (12 services)

Why it is feasible

  • CPU-only ML — tree models give microsecond inference; deployable in an enclave with no GPU.
  • All 5 architectural constraints met — read-only ingest, no decryption, streaming, measured throughput/latency, standardized schema.
  • DGA model trained at scale — 674,898 rows · Precision 0.935 · Recall 0.880 · ROC-AUC 0.972.
  • Verified end to end: /analyze/pcap on the reference capture, live Wi-Fi capture, and the dashboard.

Target audience

  • Critical-infrastructure operators — power grids, water, transport, telecom, refineries — monitoring gateway and peering links through data diodes.
  • NTRO & national CERT teams — sovereign, auditable visibility into diode-isolated enclaves without adding an attack surface.
  • SOC / OT-security analysts — one dashboard, one alert schema, MITRE-mapped evidence across IT and OT in a single passive tap.
